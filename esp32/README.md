> ⚠️ **아직 펌웨어 코드는 없습니다.** 이 디렉터리는 포팅 준비물만 담고 있습니다.
> 현재 동작하는 것은 PC 버전(`python main.py`)입니다.

## 대상 하드웨어

**Hosyond 4.0" ESP32 디스플레이** — [Amazon B0FGJJ24S1](https://www.amazon.com/dp/B0FGJJ24S1)

### 확인된 사양

| 항목 | 값 |
|---|---|
| MCU | ESP32-D0WD-V3 (ESP32-32E), 듀얼코어 LX6 @ 240MHz |
| SRAM | 520KB |
| Flash | 4MB QSPI |
| 디스플레이 | ST7796S, 4선 SPI, 320×480 |
| 패널 | TN TFT, 4.0인치 |
| 무선 | WiFi 802.11 b/g/n, BT 4.2 BR/EDR + BLE |

### ❓ 확인되지 않은 것 — **임의로 채우지 마세요**

| 항목 | 상태 |
|---|---|
| **GPIO 핀맵** | 이 SKU의 핀 배치가 공개되어 있지 않음 |
| **PSRAM** | 리스팅에 언급 없음. **없다고 가정하고 설계함** |
| **터치 방식** | 저항막(XPT2046) 추정 — 터치펜 동봉 + TN 패널이 근거. 확정 아님 |

> Amazon 상품 페이지는 자동 조회가 차단되어(HTTP 503) 직접 읽지 못했습니다.
> 위 "확인된 사양"은 검색 결과에 노출된 리스팅 내용이며,
> **실물을 받으면 반드시 대조해야 합니다.**

### 핀맵 확인 방법

실물을 받은 뒤:

1. 보드 뒷면 실크스크린과 동봉 문서 확인
2. 판매처에 데이터시트 / 예제 코드 요청
3. GitHub에서 `ESP32-3248S035` 또는 `CYD` 보드 정의를 찾아 대조
   (같은 계열이지만 **4.0인치는 핀이 다를 수 있음**)
4. I²C 스캐너로 터치 컨트롤러 확인
   - `0x38` / `0x14` / `0x5D` 응답 → 정전식 (FT6336U 등)
   - 응답 없음 → 저항막 SPI (XPT2046)

확인한 값은 `app/hardware/board.py`의 `PINS`에 채웁니다.
`PinMap.conflicts()`가 핀 중복 배정을 잡아 줍니다.

현재 상태 확인:
```powershell
python -m app.hardware.board
```

## 메모리 제약이 설계를 좌우합니다

```
480 × 320 × 2바이트(RGB565) = 300KB   ← 풀 프레임버퍼
SRAM 520KB - WiFi/TLS 스택          ≈ 180KB 가용
```

**전체 화면 버퍼를 메모리에 올릴 수 없습니다.** 따라서:

- PC처럼 "매 프레임 화면 전체를 다시 그리는" 방식은 불가능
- **부분 갱신**(바뀐 영역만 SPI로 전송)이 필수
- 웨이브 바처럼 자주 바뀌는 영역은 작게 유지 (Compact 프로파일에서 28px)

### 앨범 아트 예산

```powershell
python -m app.core.artwork
```

| 크기 | RGB565 | 디코더+TLS 포함 | 판정 |
|---|---|---|---|
| 240px | 112KB | 132KB | 가능 (여유 47KB) |
| **175px** | **59KB** | **79KB** | **가능 (여유 100KB)** ← Compact 채택값 |
| 128px | 32KB | 52KB | 가능 (여유 128KB) |

Compact 레이아웃의 앨범 아트가 175px인 것은 이 계산 결과입니다.
`tests/test_portability.py::test_compact_artwork_fits_esp32_heap`이 이 예산을 지킵니다.

## 공유 계약

PC(Python)와 ESP32(C++)가 **같은 개념을 같은 이름·같은 값으로** 쓰게 하는 장치입니다.

```
app/core/contract.py          ← 유일한 정의 (여기만 고침)
        │
        │ python tools/export_contract.py
        ▼
contract/deck_contract.json   ← 기계가 읽는 정의
esp32/include/deck_contract.h ← 펌웨어가 #include
```

**`deck_contract.h`를 손으로 고치지 마세요.** 자동 생성물입니다.
`tests/test_portability.py::test_generated_headers_are_up_to_date`가
Python 쪽을 고치고 헤더를 다시 만들지 않으면 테스트를 실패시킵니다.

### 담고 있는 것

- `enum class DeckAction : uint8_t` — 16개 액션, **고정 정수값**
- `enum class RepeatMode : uint8_t`
- `struct PlaybackState` — 고정 길이 문자열 버퍼
- `deckActionName()` — 로그용

> ⚠️ 액션의 숫자를 바꾸지 마세요. 펌웨어에 구워진 값과 어긋나면
> 버튼이 엉뚱한 동작을 합니다. 새 액션은 **끝에 추가**합니다.

## UI 설계 기준

Compact 레이아웃(`app/ui/layouts.py`의 `COMPACT_480`)이 ESP32 UI의 도면입니다.
**실물 없이 PC에서 확인할 수 있습니다:**

```powershell
python main.py --compact
```

창이 480×320으로 고정되어 실제 기기와 같은 조건에서 보입니다.

### 480×320 배치

```
┌──────────────────────────────────────────────┐
│ ● 연결됨                      기기명 · 컴퓨터 │  22px
├───────────────┬──────────────────────────────┤
│               │  곡 제목 (최대 2줄)           │
│   앨범 아트    │  아티스트                     │
│   175×175     │  ▁▃▅▂▄▁▃  웨이브 28px        │  238px
│               │  ━━━━━●━━━━  0:00 / 0:00     │
│               │    ◀   ▶   ▶▶                │
│               │  ⤮ ⟲ ♥        🔊 ━━━━        │
└───────────────┴──────────────────────────────┘
        175              263            = 438 + 마진
```

**지킨 것**: 앨범아트, 곡정보, 웨이브, 진행바, 시간, 이전/재생/다음,
셔플/반복/좋아요, 볼륨, 연결상태, 기기명 — **전 기능 유지**

**줄인 것**: 폰트(26→15pt), 버튼 지름(62→48), 웨이브(68→28px),
앨범명 줄 제거(세로 부족), 단축키 안내 제거(키보드 없음)

**터치 대응**: 진행 바 핸들을 항상 표시합니다.
터치 기기에는 호버가 없어 핸들이 숨어 있으면 잡을 수가 없습니다.

## 포팅 순서 (제안)

1. **핀맵 확정** — 위 "핀맵 확인 방법" 참고. 이게 안 되면 아무것도 못 합니다.
2. **화면 점등** — TFT_eSPI 또는 LovyanGFX로 ST7796S 초기화, 480×320 가로 회전
3. **터치 확인** — I²C 스캔으로 방식 판별 후 드라이버 선택
4. **WiFi + HTTPS** — Spotify API 도달 확인 (인증서 검증 포함)
5. **인증** — PKCE는 브라우저가 필요하므로 ESP32에서는 방식이 달라집니다:
   - 옵션 A: 기기가 AP 모드로 설정 페이지를 띄우고 폰 브라우저로 로그인
   - 옵션 B: PC에서 한 번 로그인해 리프레시 토큰을 NVS에 심어 두기
   - 어느 쪽이든 **Client Secret은 펌웨어에 넣지 않습니다**
6. **PlaybackState 채우기** — `deck_contract.h`의 구조체
7. **UI 렌더링** — LVGL 권장. `COMPACT_480` 치수를 그대로 옮깁니다
8. **입력** — 터치 → GPIO 버튼 → 로터리 엔코더 순으로 추가
9. **부분 갱신 최적화** — 웨이브 영역만 자주 다시 그리기

### 참고: PC 쪽 하드웨어 입력 템플릿

`app/input/gpio_template.py`에 물리 버튼·로터리 엔코더의 **동작 설계**가
파이썬으로 적혀 있습니다. 실행되지는 않지만 다음이 이미 반영되어 있어
C++로 옮길 때 그대로 참고할 수 있습니다:

- 버튼 채터링 180ms 디바운스 (없으면 한 번 눌러도 5번 실행됨)
- 엔코더 스텝을 150ms 모아서 **한 번**만 API 호출 (없으면 즉시 429)
